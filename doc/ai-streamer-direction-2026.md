# AI 主播方向调研与小鲸优化建议

## 1. 判断

当前小鲸更像：

```text
一个会 Live2D、会 TTS、会回弹幕、会点歌的 AI VTuber
```

但还不是：

```text
一个有固定节目、有连续内容、有观众参与机制的直播间
```

主要差距不在模型智商，而在：

- 内容结构
- 现场表演
- 观众参与
- 连续记忆
- 分发与复盘

## 2. 当前 AI 主播的四条主要方向

### A. 陪伴型

核心：

```text
情绪价值、深夜陪伴、固定人设、记住观众
```

优点：

- 留存高
- 适合长时间直播
- 对画面要求相对低

难点：

- 容易变成“随机聊天”
- 需要稳定人格和边界
- 不能被观众牵着走

适合小鲸的程度：高。

### B. 故事型 / 电台型

核心：

```text
连续故事、深夜电台、观众投稿、章节悬念
```

优点：

- 内容密度高
- 可以切片传播
- 观众有“追更”理由

难点：

- 需要故事库和章节状态
- 长文本 TTS 容易单调
- 需要中断/恢复机制

适合小鲸的程度：很高。当前已经做了第一版长故事模式。

### C. 互动游戏型

核心：

```text
猜歌、猜台词、二选一、投票、故事接龙、挑战
```

优点：

- 弹幕参与感强
- 节奏快
- 容易产生高光片段

难点：

- 需要游戏状态机
- 需要防剧透/防刷
- 需要裁判和计分

适合小鲸的程度：高，适合做 10～20 分钟的小段。

### D. 角色扮演 / 多角色型

核心：

```text
小鲸 + 其他角色、不同声线、场景小剧场
```

优点：

- 内容差异大
- 适合切片
- 可以形成角色 IP

难点：

- 多音色 TTS
- 角色切换和剧本控制
- 版权和内容安全

适合小鲸的程度：中高，建议后做。

### E. 知识/热点型

核心：

```text
冷知识、科技/游戏/动画话题、观众提问
```

优点：

- 容易建立“聪明”标签
- 可搜索、可切片

难点：

- 事实核验
- 政策和版权风险
- 容易变成念稿

适合小鲸的程度：中，作为点缀，不做主线。

## 3. 推荐定位

不建议把“万能 AI 助手”当主线。推荐：

```text
深夜陪伴型 AI 主播
+
连续故事电台
+
轻互动游戏
+
网易云点歌
```

一句话定位：

```text
一个嘴硬心软、会讲故事、会陪聊、会放你喜欢的歌的蓝鲸娘主播。
```

这样和现有能力最匹配：

- 已有 Live2D + TTS
- 已有点歌 / 网易云喜欢歌单
- 已有故事模式
- 已有弹幕和礼物优先级

## 4. 内容栏目建议

### 固定开场

```text
今天几号、星期几
今晚的主题
今晚的故事类型
今晚的点歌规则
```

### 固定栏目

#### 1. 今日话题（5 分钟）

小鲸抛一个问题，观众回答，抽取几条回应。

#### 2. 连载故事（15～25 分钟）

```text
讲个故事
继续
别讲了
换一个故事
```

每一段结束在悬念处，下一段用“继续”接。

#### 3. 猜歌 / 猜台词（10 分钟）

播放 3 秒前奏或念一句台词，观众猜。

#### 4. 二选一（5 分钟）

```text
A：继续故事
B：换一个故事
A：唱一首
B：聊一会儿
```

#### 5. 树洞 / 夸夸（10 分钟）

读审核后的观众投稿，给一句真实的回应。

#### 6. 晚安收尾（5 分钟）

固定 BGM、低能量、明日预告。

## 5. 技术优化优先级

### P0：内容状态机

当前故事、点歌、礼物、普通聊天是分散处理的。建议引入：

```text
ContentDirector
  current_segment
  segment_started_at
  segment_duration
  next_segment
  audience_vote
  story_chapter
  interruption_policy
```

没有这个状态机，直播会一直是“随机回应”。

### P0：多角色/多音色

故事里的旁白和角色对话现在共用小鲸音色，听起来会平。

建议：

```text
旁白：小鲸主音色
角色 A：更轻/更幼
角色 B：更低/更慢
角色 C：气声/神秘
```

先做 2～3 个音色，不要一开始做很多。

### P1：TTS 表现力

当前 TTS 是“把文字读出来”，缺少：

- 停顿
- 呼吸
- 轻笑
- 疑问/惊讶语气
- 句尾起伏
- 角色区分

可以先在文本层加轻量表演标记，再由 TTS 预处理映射：

```text
[停顿]
[轻笑]
[压低声音]
[疑惑]
```

不要直接输出 SSML 给观众看。

### P1：打断与抢占

故事模式已经可以中断，但还要完善：

```text
礼物 > 运营指令 > 普通弹幕 > 故事续讲
```

以及：

```text
打断后是否恢复
恢复时从哪一段继续
礼物感谢后自动接回故事
```

### P1：观众记忆

已有 viewer profile / memory，但直播中没有明显体现。

可以做的“轻记忆”：

- 记住常来观众的名字
- 记住上次聊过的话题
- 不主动提隐私
- 用“上次你说……”制造连续感

注意：

```text
不要声称记得没记住的事
不要让新观众觉得被排除
```

### P2：视觉表演

当前视觉主要是 Live2D 模型 + 字幕 + 背景。

可加：

- 情绪动作与台词同步
- 故事场景切换
- 镜头推近/拉远
- 礼物特效
- 章节标题卡
- 猜歌倒计时

这比继续堆字幕更有效。

### P2：切片与分发

每场直播自动保留：

```text
故事高光
猜歌高光
礼物感谢
嘴硬名场面
```

生成：

```text
竖屏切片
字幕
标题
话题标签
```

直播间的流量不只来自直播本身，也来自切片。

### P2：数据看板

需要看：

```text
平均停留
每分钟弹幕
关注转化
回访观众
故事继续率
点歌成功率
礼物感谢响应时间
```

不要只看在线人数。

## 6. 当前最值得先做的 5 件事

1. ContentDirector 栏目状态机
2. 故事章节 + 观众选择 + 中断后恢复
3. 猜歌模式
4. 多音色故事角色
5. 直播切片/高光导出

## 7. 不建议现在做

- 一上来做复杂 3D 场景
- 一上来做多主播联动
- 大量角色同时说话
- 纯知识型日更
- 依赖礼物诱导的互动
- 继续在 effects.js 里堆视觉补丁

## 8. 结论

小鲸最适合的方向不是“万能 AI”，而是：

```text
有连续故事
有固定栏目
有观众选择
有音乐陪伴
有嘴硬心软人格
```

先把“节目感”做出来，再谈更复杂的视觉和多角色。
